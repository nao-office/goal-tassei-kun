# ゴール達成くん

毎日のセルフエフィカシーワーク、ゴールの確認、アクション管理、週次レビューを一つにつなぐ静的Webアプリです。

## 両方残す自動連係（2026-11-07）

この節が今回の変更の自動連係仕様です。公開済みかどうかは対象PR・デプロイ結果で確認してください。従来の「Sheets側に変更があれば停止し、毎回差分を選ぶ」運用から変更しています。

- 「Google連携 → 両方残して自動連係」を有効にすると、アプリを開いている間、朝・夜のワークとアクション一覧の対応項目を送受信します。Sheets側の普通の更新や競合だけで、毎回の項目選択を求めません。
- 同じ項目で内容が分かれた場合、同期対象の双方の内容を、同じスプレッドシートの **「同期の別記録」** に保存・検証してから処理を続けます。通常画面は競合した項目だけSheets側の値に揃え、端末側の異なる内容は別記録に残します。競合していない端末側の更新は送信します。
- 書き換え前の別記録は内容のSHA-256で識別し、再試行では既存の同内容を再利用します。大きい記録は分割して保存し、全断片とハッシュを確認できるまで「保存済み」と扱いません。ワーク記録へ同じ日付の別行を増やして競合を保管する方式ではありません。
- 「両方残した別記録 → 別記録を読み取る」で保存された候補を参照できます。Sheets上の別記録は「別記録も含めてバックアップ」で端末の内容と一緒に退避できます。詳細は次節を参照してください。
- 端末だけの週次レビュー、講義一覧・複数講義のメモ、アクションの事実/GAP等を新たにSheetsへ送るものではありません。ゴール・ゴールの種は引き続き手動同期です。削除の自動伝播はせず、Sheetsから消えた行でも端末に意味のある記録が残る場合は別記録を保管して復元します。
- 比較中にSheetsの更新が続く場合は最新内容から最大2回計画し直し、それでも続くと60秒以上待って自動再試行します。毎回の差分選択は要求しません。
- 対応データの保存上限（1項目4,000文字、ワーク5,000件等）を超える受信内容は、切り詰めず停止します。読み取り範囲外のIDを未登録と誤認しないよう、ワークのシート総行数5,001行・アクション1,200行以内も確認します。
- 保存容量不足、認証、通信、見出し違い、不完全な別記録等は競合とは区別して停止し、理由を画面移動後も保持します。直ったら「自動連係を再試行」で再開します。復元後は従来どおり自動連係を停止し、利用者が明示して再開するまで送信しません。
- **限界:** Google Sheets APIには複数端末共通の排他更新がありません。読み取り後の完全同時編集や、別記録を保存しない外部ツールとの更新競合を完全には防げません。新規の日付・アクションIDを別端末が完全同時に追加すると、両方の内容は別記録に保管されますが、通常行が重複して安全停止することがあります。この状態は再試行だけでは直らず、各端末のJSONとSheetのコピーを確保して重複行を確認する必要があります。アプリは自動削除しません。厳密な防止にはサーバー側の直列化等が必要です。既存の実データや権限を使ったテストは行いません。

`keep-both-sync.test.js` と `browser-keep-both.test.cjs` が、この自動連係の計画・別記録・再試行・複数端末の回帰テストです。実Googleアカウント、実Google Sheets、実iPhoneの確認とは別の、架空データ・モック通信による検証です。

## 同期画面の整理（2026-11-10）

- 普段の操作は「両方残して自動連係」と「ゴールを同期」に分けました。ワーク・アクションの毎回の差分選択は不要です。
- 「ゴールを同期」はゴール一覧・変更履歴・確認履歴・ゴールの種だけを読み取ります。確認後の取り込み・保存、既存値の消去確認は従来どおり維持しています。
- 「詳細・復旧」は初期状態で閉じています。接続設定、再ログイン、JSONバックアップと復元、別記録の閲覧・コピー、CSV取り込み、ワーク・アクションの個別確認をここにまとめました。
- ログイン完了だけではSheetsの比較を開始せず、自動連係も開始しません。利用者が同期方法を選びます。
- 手動確認を表示している間だけ自動連係を待機します。閉じる、詳細・復旧を畳む、別画面へ移る操作で確認を破棄して再開します。読み取りや認証の途中で移動・取消した場合、遅れて届いた結果で確認画面を再表示したり、ゴールを保存したりしません。
- 両方を残す処理、保存データの形式、同期の別記録、復元後の安全停止は変更していません。講義CSVの取込処理はこの変更の対象外です。
- `browser-sync-navigation.test.cjs` は認証後に比較しないこと、ゴールのみの読取・取込・保存、確認終了後の自動再開、途中の画面移動を架空データで検証します。ChromiumとiPhone画面設定のWebKitをCI対象とし、実Google／実iPhoneの検証とは区別します。

## 別記録のバックアップと再利用（2026-11-08、未公開）

- Google連携の「別記録も含めてバックアップ」は、接続先Sheetsを**読み取りのみ**で取得し、現在の端末データとまとめてJSONにします。完全な版だけでなく未完の分割行、取得元Sheets ID・取得日時も保持します。認証・通信・検証失敗時には端末だけのファイルを代わりに作って成功扱いしません。
- 同期の別記録タブがまだない場合も、その取得時点の「なし」を記録します。復元済みの過去の別記録は削らず、今回のスナップショットを追加します。複数回のスナップショットに同じ版が含まれる場合はそのまま保管します。
- 通常のJSON復元で別記録も端末に復元します。Google連携の「復元済みの別記録を開く」から、Google接続なしでハッシュを検証して閲覧できます。未完の版はコピーできません。復元ではSheetsへ書き戻さず、自動同期は既存仕様どおり停止します。
- 「端末のJSONバックアップ」に含まれる別記録は**既に復元したものだけ**です。最新のSheetsの別記録が必要な時は「別記録も含めてバックアップ」を使ってください。
- 「元を残して編集欄へコピー」はまだ保存・送信しない専用編集欄です。ワークは今日の対応する文章の**末尾へ追記**し、既存の文章や達成チェックは残します。誤った講義への紐づけを防ぐため、講義固有メモと講義ID・達成状態はコピー対象外です。アクションは別IDの新規「未着手」として保存します。保存後は通常の同期対象です。
- 1項目4,000文字、通常バックアップ20MB等の上限や端末容量を超える場合は、内容を切り詰めず停止します。保存失敗時はコピーの編集内容を残して再試行できます。JSONには個人のワークと元のSheets IDが含まれるので、共有せず安全な場所に保管してください。
- 実Googleへの接続・書き込みはこの開発検証では行いません。実iPhone / iPadの確認と公開は別工程です。


## 保存失敗とバックアップの保護（2026-11-07）

- 自動取り込み後に入力欄からフォーカスを外しても、未保存のアクション・週次レビュー・ゴールのフォームは描き直さず入力を保ちます。確定は各フォームの保存ボタンで行います。
- 朝の確定、夜の振り返り完了、講義の復習完了は、端末保存に成功した場合だけ成功表示と画面切り替えを行います。失敗時は入力を残し、同じボタンで再試行できます。アクション・週次レビューの保存失敗でもフォームを閉じず、再試行で変更履歴を重複させません。
- 保存失敗中は自動同期の予約・送信を開始しません。上部に「端末保存を再試行」「JSONで退避」を表示します。再試行は端末内の記録の保存であり、編集中のフォームは各画面の保存ボタンで確定してください。保存できるまではページを閉じたり再読み込みしたりしないでください。
- 通常のJSONバックアップは書き出し・復元とも **20,000,000 UTF-8バイト（20MB）以下**。改行・字下げを省いたJSONで書き出します。従来の2MB超のバックアップも、現在のデータ形式に合い、内容を省略せず保存できる場合は復元できます。端末の保存容量は別の制限なので、20MB以下でも保存できるとは限りません。
- 件数や文字数の切り詰め、未対応項目の破棄が必要なファイルは、黙って一部だけ復元せず中止します。通常復元できない現在のデータは、明示確認後に内容を削らない「救出用JSON」として退避できます。救出用JSONは通常復元の対象外で、手動の確認・移行用です。
- 復元の取消、形式エラー、容量超過、読み取り失敗は現在の記録を置き換えません。端末への保存に失敗した場合も従来の記録を維持します。復元を開始すると安全のため自動同期を停止し、成功後も再確認まで停止を保ちます。

### 公開前の端末確認（手動経路と自動経路）

1. iPhoneとPCでそれぞれJSONバックアップを保存し、本番データとは別のテスト用シート・テスト用ブラウザー環境を使います。
2. 前夜の一歩のある日・ない日、朝の既存入力、上書きのキャンセル、4問と任意の深掘りの順番を確認します。
3. 端末保存、オフライン、Googleの認証期限切れ、送信成功・失敗を区別できるか確認します。再読み込み後に以前の送信を新しい成功として表示しないことも確認します。
4. PCからテスト用シートに保存した後、iPhone側の「差分を確認（読み取りのみ）」で変更を確認します。この手動経路では選ぶまで既存の記録が変わらないことを確認します。
5. 両端末で「両方残して自動連係」を有効にし、片方ずつ架空のワーク・アクションを変更して相手に反映されることを確認します。異なる値は「同期の別記録」に双方が残ること、通信・容量エラーを成功表示しないこと、入力中のフォームが消えないことも確認します。

- 成長の記録：月別にまとめ、日を開くと行動・できたこと・成長・次の一歩が読めます。成長コレクションと復習履歴は別グループです。

## v1.2｜開くだけで自動同期（Cloudflare Worker方式・要初回設定）

従来のGoogle OAuthはページ再読み込みのたびに再接続が必要でした。**Cloudflare WorkerにGoogleの更新用認証情報を暗号化して保存する方式**を追加し、PC・iPhoneそれぞれで初回ログインした後はアプリ起動時に自動接続できます。Googleの許可取り消し・期限切れなどでは再ログインが必要です。

**重要：PRのマージだけでは有効になりません。** Cloudflare WorkerとGoogle Cloudの設定を完了し、アプリの「Google連携」でWorker URLを1回登録してください。設定がない間は従来のワンタップ再接続方式を維持します。既存の記録・同期基準情報は削除しません。

**[Cloudflare Workerの導入手順はこちら](worker/README.md)**。初回はPC・iPhoneでJSONバックアップを取り、両方向の同期をテストしてください。アプリを閉じている間のバックグラウンド同期や、完全同時編集の厳密な競合防止は保証しません。

## できること

- **ゴール**：1か月・3か月・1年・3年・5年、テーマ別、定性・定量のゴールを表示。ゴールの変更履歴・定期確認履歴も閲覧。
- **朝のワーク**：未来の自分、今日の最重要アクション、最低限の完了ラインを記録。
- **今日の振り返り**：実行チェック、学び、昨日までの自分との差分を記録。
- **アクション管理**：ゴールIDとの関連付け、完了条件、期限、優先度、進捗、事実・GAP・技術課題・適応課題。
- **週次レビュー**：実績、GAP、技術課題・適応課題、学び、翌週の集中領域、コントロール可能な行動。
- **変更履歴**：アクションと週次レビューの更新前後のスナップショットを保管。
- **朝との連動**：アクション一覧や週次レビューから、今日の朝のワークの最重要アクション／最低ラインに転記（既存の入力があれば上書き確認）。
- **バックアップ**：「Google連携」などの画面からJSONを書き出し／復元。

## 記録の保存場所（重要）

- 朝・夜、アクション、週次レビューはまず **このブラウザの localStorage に保存** します。JSONバックアップにアクション・週次レビューも含みます。
- Google連携の「差分を確認」は「ワーク記録」「アクション一覧」を読み取ります。選択して同期するまでは端末データ・同期基準・Sheets・Drive設定を変更しません。
- 両方残す自動連係は、朝・夜のワーク記録とアクション一覧の対応列を送受信します。異なる内容は「同期の別記録」に保管・検証してから反映し、初回も項目ごとの選択は不要です。削除は自動伝播しません。認証・通信・保存容量・元行の重複等の問題は停止して理由を表示します。
- ゴール一覧・ゴール変更/確認履歴・ゴールの種は、Google連携画面で読み取り比較後に手動同期できます。ゴールの自動同期は行いません。ゴール・ワーク・アクション以外の講義カタログ、アクション候補/履歴、週次レビュー/履歴、週間計画、朝のゴールスナップショット、複数講義の復習メモ、アクションの事実・GAP・今週計画などはこの同期画面の対象外です。
- ゴールの変更履歴をGoogle Sheetsへ保存するには、既存の「ゴール履歴」タブのQ:S列に、順に `変更ID`、`変更前スナップショット（JSON）`、`変更後スナップショット（JSON）` の見出しが必要です。アプリはシートの列や見出しを自動変更しません。追加列がない場合、変更履歴を含む書き込みを停止します。既存のA:P列と他のタブは変更しません。
- ゴール一覧で同じIDの値が異なる場合は競合として選択を求めます。Sheetsの未設定値で端末の既存値を消す選択には、消去される項目を表示する別の確認が必要です。旧形式のVISION/BEは「ゴール一覧」内の予約ID行で扱い、専用タブを追加しません。
- Google認証で取得したアクセストークンは永続保存しません。「差分を確認」は読み取りだけで、その手動経路では「確認した差分を同期」を押すまで書き込みません。両方残す自動連係を有効にした場合は、対象項目と別記録へ自動で書き込みます。

## 操作例

1. 「Google連携」でゴール一覧を読み込む（未連携でもアクション登録可能）。
2. 「アクション」で実行内容・最低ライン・関連ゴールを登録。
3. 「今日のワークに使う」で、最重要アクションを朝のワークへセット。
4. 夜に振り返り、週末に「週次レビュー」で事実・GAP・次週の一歩を決める。
5. ときどき「変更履歴」を確認し、JSONバックアップを書き出す。

このアプリはGitHub PagesなどのHTTPS上で開く構成です。Google Sheetsの同期にはOAuth設定が必要です。

## Google Sheets同期の安全確認

Googleとの接続で「401」または接続期限切れが表示された場合は、「Google連携」画面の「Googleに再ログイン」を押してください。認証情報だけを更新し、端末の記録・Sheetsの記録・スプレッドシートIDは変更しません。「Googleに再ログイン」は認証更新用です。自動連係を再開する場合は「両方残して自動連係」または「自動連係を再試行」を押します。任意で「差分を確認（読み取りのみ）」も使えます。

通常のGoogle OAuthでは、自動同期が停止中なら「差分を確認」時に読み取り専用の権限を使い、選択した内容を書き込む段階で書き込み権限を追加確認します。自動同期中は動作を維持するため既存の書き込み権限を使います。Cloudflare Worker経由の既存ログインも、自動同期との互換性のためSheetsの読み書き権限とDriveアプリデータ権限を含みます。Worker経由では差分確認と書き込みの権限を分離していません。

1. 普段は「両方残して自動連係」を開始します。ワーク・アクションの通常の更新や競合で、毎回の差分選択は求めません。復元後は自動連係を停止しているので、内容を確認してから明示的に再開してください。
2. 自分で選びたい場合は「差分を確認」を開き、「端末の記録」「Google Sheetsの記録」「今は決めない」から選べます。この任意の手動経路は、選択がすべて決まるまで書き込みません。
3. 手動の「確認した差分を同期」は書き込み直前にSheetsを再取得し、プレビュー後に変更されていれば中止します。自動連係側は最新内容から計画し直し、更新が続けば待って再試行します。
4. ゴールとゴールの種は手動同期のままです。端末専用データは自動共有されません。端末を変更する前にはJSONバックアップを保存し、Sheets側の別記録はSheet自体を別に保管してください。

この安全同期機能のテストはテストデータとモック通信で実施します。実Googleアカウント・実Google Sheetsとの通信動作を保証するものではありません。実Google通信テストは未実施です。

### 全データ同期の設計候補（未対応データ向け）

以下は全データへ対象を広げる将来案です。今回のワーク・アクションの両方残す自動連係は冒頭の仕様を参照してください。

既存のタブ、見出し、ID、端末データはそのまま残し、すぐに既存データを置き換えない段階移行を推奨します。将来の同期用に、型付きID・変更イベントID・変更元端末・親となる版・変更日時・形式バージョン・変更内容を記録する**追記型の「アプリ同期イベント」タブ**を追加する案があります。イベントIDで再送による重複を判定し、変更元の版が一致しない場合は競合として止めます。削除は即時に行わず削除マークとして扱い、ユーザーが確認するまで既存値を保持します。

初回移行は、既存タブと各端末のJSONバックアップを退避し、まず読み取り専用の差分・件数レポートを作成します。同じIDで異なる内容は自動で片方を選ばず、既存の端末データとSheetsの値を両方保持します。新しいタブや列を追加する場合も、本番シートをアプリが勝手に変更しないようにし、実施前に利用者の確認を得ます。

Sheets APIには複数端末の書き込みを一括で排他制御する仕組みがありません。直前の再読み込みだけで同時編集を完全に防げるとは限らないため、版の不一致・重複イベント・通信の部分成功を検出したら同期を保留し、無条件再送や自動削除を避ける設計が必要です。追記型データの増加に備えた保管量・整理方針も、実装前に決めます。

1. **仕様と移行計画**：全データの列・ID・版・削除マーク・イベント形式を確定し、バックアップ、検証、復旧手順を用意します。モックで既存タブを読み取るだけの差分レポートを検証します。

各PRで対象を限定してテストし、実Google Sheetsとの通信確認はモックテストと区別します。本番シートの列追加やタブ追加が必要な段階では、手順と復旧方法を先に案内し、承認前に実行しません。

## v0.7｜ChatGPTとの会話からゴールを育てる

Google Sheetsの「ゴールの種」タブに、会話で見つけた目標・価値観・理由などの材料を蓄積します。

| 状態 | 意味 |
|---|---|
| 要確認 | 発言の内容は記録したが、期間・達成条件・採用意向などが未確定 |
| 確認済み | 本人に内容を確認した材料。正式なゴールに採用する前の段階 |
| ゴール反映済み | 正式ゴールに採用済み。関連ゴールIDを記録する |
| 保留 | いまは追わないが、履歴として保存 |

- 毎朝のセルフエフィカシーワークでは、まず既存の質問を進め、その回答から本人が明確に述べたゴールの材料を見つける。
- 新しく見つけた材料は内容が明確な場合だけ「ゴールの種」に記録。推測で期限・期間・数字を作らない。
- 毎朝の深掘りは1回1問を目安に。既存の材料の「次に確認したい質問」を優先し、前回までに分かったことを繰り返し質問しない。
- 目標の期間・定性／定量・未来の景色・在り方（BE）・理由が決まったら、本人が確定した内容を「ゴール一覧」に登録する。作成／変更日時・理由を「ゴール履歴」に追加する。
- ゴール管理の保存と、朝・夜の「ワーク記録」の保存は別。ワーク記録は従来どおり「今日のワークを保存して」と指示されたときだけ。
- ChatGPTの会話からGoogle Sheetsを更新するにはChatGPT側の接続が必要。アプリからChatGPTの会話を自動取得する機能や、会話終了後の常時バックグラウンド処理はありません。アプリ内の朝・夜・アクション編集は、v0.9で本人が書き戻しを押した場合にGoogle Sheetsへ送信できます。
- アプリの通常同期は読み取り専用。v0.9の書き戻しボタンから限定した既存タブへの編集を実施できます。Google認証がまだできない場合は「ゴールの種」タブをCSV出力して読み込めます。
- ゴールの種はプライベートなGoogle Sheetsに保存。GitHubの公開リポジトリ内には個人的な発言の内容、スプレッドシートID、OAuthの秘密情報を保存しません。

### Google Sheets：ゴールの種 の列

`材料ID / 記録日（JST） / テーマ / 期間 / 項目 / 会話で明らかになった内容 / 状態 / 次に確認したい質問 / 関連ゴールID / 出典・会話日 / 最終更新日（JST） / メモ`

### ゴール育成の流れ

1. 朝の会話で質問に答える（既存のワークは維持）。
2. 会話で得た明確な材料を「ゴールの種」に記録する。内容があいまいなら「要確認」で残す。
3. 確認した内容は適切な項目に紐付け、期間別の正式ゴールへ段階的に昇格する。
4. アプリの「Google連携」で同期し、「ゴール設定」に表示された材料と進捗を確認する。
5. 次の日は未回答の質問から深掘りを続ける。

## v0.8｜会話からアクションと週間計画を育てる

「ゴールの種」と同じ考え方で、ChatGPTとの毎朝・夜・週次の会話から **行動の候補 → 合意したアクション → 週間計画 → 実績と変更履歴** を育てます。

### Google Sheetsに追加したタブ

- **アクションの種**：本人が言及した、今後やってみたいこと。候補であり、期限や着手を勝手に確定しない。
- **アクション一覧**：実行することを本人が確認した正式なアクション。安定したアクションID、関連ゴール、テーマ、完了条件、最低限ライン、期限、優先度、状態、進捗メモ、課題など。
- **アクション履歴**：作成・変更・達成を記録。IDは引き継ぎ、更新後の状態を追記。
- **週間計画**：対象週の月曜をキーとして、今週のフォーカス・最重要アクション・最低ライン・実績・次の一手を記録。

### 毎朝・夜・週次の使い方

1. 朝：「いつものワークを始めよう」。質問3で今週のアクションを振り返り、今日の行動へ具体化する。
2. 夜：「今日の振り返りを始めよう」。実行した事実・未達成の原因・学び・次の一歩を明らかにする。
3. 週次：「今週のアクションを見直そう」。確認済みゴールをもとに、今週・来週・将来の候補を見直す。
4. 「アプリのGoogle連携」でアクションの種・一覧・履歴・週間計画を同期し、「アクション → 今週・将来」に表示。
5. Google OAuthが設定されていなければ各タブのCSVをGoogle Sheetsからダウンロードして取り込める。

### 明確な区別

- 「アクションの種」は、会話中に明確に話した候補を記録できる。本人が同意していない候補を、今週の確定アクションにしない。
- 「アクション一覧」「週間計画」の登録・状態変更は、本人の明確な確認に基づく。
- 進捗は本人が実行したと述べた事実に基づく。予定だけで「完了」にしない。
- **ワーク記録タブ**は従来どおり「今日のワークを保存して」「今日の振り返りを保存して」の明示指示を守る。
- **v0.8まではGoogle連携は読み取り専用。v0.9から** 朝・夜のワークとアクション一覧の対応する列は、明示的な書き戻しでGoogle Sheetsに保存できます。正式ゴールや『ゴールの種』などは読み取り専用を維持します。
- JSONバックアップにはアクション・週次レビュー・同期済みアクション候補と週間計画が含まれる。バックアップは定期的に取ること。
- GitHubリポジトリには個人の行動・ゴールを直接埋め込まない。

### 次に発展させる機能

週次レビューの詳細・アクション内部専用フィールド（事実・GAP・今週の紐付け等）・正式ゴールの承認付き更新など、v0.9の書き戻し対象外データも安全に共有する。


## Google Sheets連携設定（安全同期）

保存先のスプレッドシートIDは各ブラウザーに個別に保存します。別の端末では同じIDを入力してください。安全同期はGoogle Driveのアプリ専用領域に設定を書き込まず、差分確認は対象タブの読み取りだけを行います。既存のDrive設定ファイルや記録は削除しません。

- 「差分を確認」で端末の記録と「ワーク記録」「アクション一覧」を比較し、各差分で残す側を選びます。
- 同じ差分確認で「ゴール一覧」「ゴール履歴」「ゴール確認履歴」「ゴールの種」も読み取り、端末側のゴール管理と比較します。Sheetsにだけある記録はまとめて端末へ追加でき、端末側に同じIDがある場合は上書きせず選択を求めます。削除は行いません。
- ゴール画面から正式ゴールを登録・編集できます。変更前後の内容を端末の履歴に残し、別端末へ同期するときは確認済みの差分だけを手動で保存します。変更履歴と確認履歴はSheetsへ追記し、既存行は更新・削除しません。
- 既存の「ゴール一覧」列は維持します。旧形式VISION/BEは同じタブ内の予約ID `__goal-tassei-legacy-vision__` を使い、新しいタブや列は作りません。
- 変更前後のゴール内容をSheetsに残すため、「ゴール履歴」タブのQ:S列に `変更ID`、`変更前スナップショット（JSON）`、`変更後スナップショット（JSON）` の見出しが必要です。既存のA:P列はそのまま残します。アプリはSheetsの見出しを自動変更しません。見出しが未設定の場合、ゴール履歴を含む書き込みを停止し、必要な操作を案内します。
- Sheetsにだけあるワーク記録・アクションは、差分画面の「Google Sheetsの記録をまとめて取り込む」で一括追加できます。既存の端末側の値は上書きせず、Sheetsへの書き込みも行いません。取り込み直前にSheetsの内容を再確認し、プレビュー後に変更されていれば取り込みません。
- 差分の件数は「差分のある記録」「比較した記録」「差分項目」に分けて表示します。1つの記録に複数の項目差分がある場合も、記録数と項目数を混同しません。
- 初回取り込み後も自動同期は停止状態です。端末の記録を確認してから、改めて差分確認と同期操作を行ってください。
- 書き込み権限は、選択した差分を同期する操作の後にだけ要求します。
- 一度同期基準ができた後も、自動同期の直前にSheetsを再確認します。競合・Sheets側の変更・削除や空欄化の可能性・通信や保存の失敗があれば停止します。
- OAuthアクセストークンは永続保存しません。別端末での接続にはそれぞれGoogle認証が必要な場合があります。
- OAuth WebクライアントIDは秘密情報ではなくWebアプリの共通設定として利用できます。公開リポジトリにスプレッドシートIDや記録、クライアントシークレットを保存しないでください。
- ゴール管理の同期は手動のみです。ワーク記録・アクション一覧の既存自動同期には追加せず、復元後の安全停止や既存の競合保護にも影響させません。

旧バージョンが使っていたGoogle Driveの設定ファイルは、安全同期では読み書きしません。Cloudflare Workerの既存OAuth設定には互換性のためDriveアプリ領域スコープが残っていますが、このアプリの差分確認・同期では使用しません。


## v1.1｜Google認証切れの案内とワンタップ再接続（当時の変更履歴）

- 自動同期を有効にした端末では、全画面の上部に同期状態を表示します。端末内保存済み・Googleへ保存待ち・保存中・最終同期時刻を確認できます。
- Google認証が切れた場合は、画面上部に **「Googleに再接続」** ボタンを表示します。Google連携画面を探さなくても、押して再認証すれば自動同期を再開します。
- 認証が切れている間の入力は端末内に保存し、Google Sheetsへ保存済みとは表示しません。競合・削除行を検知した場合も勝手に上書きしません。
- ブラウザーのポップアップブロックを避けるため、画面の読み込み・復帰・定期タイマーからGoogleの認証ポップアップを自動起動しません。**再接続ボタンは本人のタップ／クリックで押す必要があります。** Google OAuthのトークンは安全のためブラウザーに永続保存しないため、ページ再読み込み後も再接続が必要になる場合があります。
- 自動読み込みは接続済み・画面表示中に実行されます。Safariでアプリを閉じている間のバックグラウンド同期は保証されません。

## v1.0｜Google Sheets自動同期（当時の変更履歴）

以下は当時の仕様で、現在の同期対象・競合処理は冒頭の節が優先します。

1. **最初に** iPhoneとPCの両方で「端末のJSONバックアップ」を保存する。
2. GitHub Pages上の「Google連携」画面で、**「自動同期を有効にする」** を端末ごとに押し、Googleの書き込み権限を許可する。これ以降、ボタンでの保存・読み込み操作は通常不要。
3. 朝・夜の入力とアクションの変更は端末内に即時保存し、入力が落ち着いて約1.8秒後にGoogle Sheetsへ送信する。書き込み後は再取得して検証し、他端末との競合を検知したら上書きしない。
4. 端末が表示中で、入力フォームを操作していないときは約2分ごとに最新情報を読み込む。画面へ戻ったときも更新を試みる。リアルタイムのプッシュ配信ではない。
5. アプリ再起動時は保存済みの設定を使ってGoogleの再認証を試みる。**OAuthトークンは永続保存しない**ため、ブラウザーの制約や有効期限により「自動同期を再接続」を押す必要がある場合がある。
6. 同期エラー・競合・削除行を検知したら自動上書きせず停止／保留する。Google連携画面で状況を確認し、必要ならJSONバックアップを保存してから対処する。

**同期対象**：「ワーク記録」の朝・夜・講義復習列、「アクション一覧」の対応列、「アクション履歴」の追記。ゴール・ゴールの種・週間計画・アクションの種などは引き続き読み取り専用。週次レビューの端末専用項目は自動書き戻し対象外。

**注意**：2台が完全同時に編集した場合、Google Sheets APIは厳密な排他トランザクションを提供しません。既存の直前比較と再読込によって競合リスクを下げますが、完全には防げません。テスト時はまず片方の端末で変更し、もう片方へ反映されたことを確認してください。

## v0.9｜iPhone・PC向けの双方向同期（朝・夜／アクション）

1. **最初に** iPhoneとPCで既存の記録をJSONでバックアップする。初回同期時にも端末内の原本バックアップを別保存する。
2. アプリで朝のワーク・夜の振り返り・アクションの内容を変更する（端末内に保存）。
3. Google連携の **『Google Sheetsに保存して同期 ↑』** を押す。初回のみGoogle Sheetsの**書き込み権限**（`https://www.googleapis.com/auth/spreadsheets`）への許可が必要。Google CloudのOAuth同意画面でも該当スコープを登録する。
4. 同じGoogle Sheets上の項目が別端末やChatGPTですでに変更されていた場合、競合メッセージを表示して**自動上書きしない**。
5. 変更がなければ該当セルのみ保存し、更新内容を再取得して照合する。アクションの更新履歴は『アクション履歴』に追記する。
6. もう一方の端末では **『Googleに接続して同期 ↻』** を押して最新データを取り込む。ローカルに未送信の変更がある場合、誤上書き防止のため読み込みを停止する。

### 対象・非対象

- 書き込み対応：『ワーク記録』タブ内の朝6項目、実行チェック、夜の振り返り・講義復習、ならびに『アクション一覧』の対応18列と『アクション履歴』への追記。
- 読み込みのみ：『ゴール一覧』『ゴール履歴』『ゴール確認履歴』『ゴールの種』『アクションの種』『週間計画』など。
- **未対応**：週次レビューの端末内専用記録、アクションの端末内だけの付加属性、下書き中のゴール、完全自動・常時リアルタイム同期、Google Sheetsへの自動保存。操作していない端末には自動でデータが配信されないため、その端末で読み込みを実行すること。

### データ保護上の注意

- スプレッドシート全体へのOAuth書き込み権限をGoogleが要求しますが、アプリのコードは設定済みの専用スプレッドシートの指定タブ／指定列だけを書き換えます。
- 競合チェックは **書き込み直前の読み直しによるもの** で、複数端末で完全同時に書き込む場合の厳密なトランザクション保証ではありません。通常は1台で編集→保存→他端末で読み込みの順に操作してください。
- ChatGPTがワークを保存するための明示的指示ルールは引き続き適用。アプリ上の保存ボタンは、本人が操作した時のみデータを送信します。
- 本番利用前に iPhone・PC 両方からテストし、既存データと履歴が壊れていないことを確認してください。
